# TimeCapsule · 时间胶囊

[![CI](https://github.com/8adss/timecapsule/actions/workflows/ci.yml/badge.svg)](https://github.com/8adss/timecapsule/actions/workflows/ci.yml)

**中文** | [English](README.en.md)

> 写给未来的自己，然后等着收信。

把此刻的决心封成一枚**时间胶囊**，定在未来某一天开启。在那之前，用任务清单一天天兑现它；连续打卡、成长等级与成就徽章会记录你走过的路。

**本地优先**——没有账号，没有服务器，所有数据都存在你自己的浏览器里，断网也能照常用。

---

## 特性

| | |
| --- | --- |
| **时间胶囊** | 写下想对未来说的话，指定开启日期。到期后**自动开启**，不是提醒你去点，而是真的到了时候自己出现 |
| **任务清单** | 创建 / 编辑 / 放弃，按类别与截止时间管理；过了截止时间自动标记为已逾期 |
| **知识库** | 导入你写过的自我介绍、日记、笔记等资料，支持编辑、搜索与排序。它是「我的分身」的材料来源 |
| **我的分身** | 把知识库里的资料整理成「某个时间点的自己」——画像与说话风格现在手写，接上大模型后可一键生成。胶囊记的是写下那句话时的我，分身记的是何时的我 |
| **对话** | 和「过去的你」（已开启的胶囊）或「何时的自己」（分身）聊天。分身会从它引用的那几篇材料里**召回相关片段**当作「记得的事」，所以它答的是你真实经历过的事。**这是唯一会联网的功能**，用你自己的 API Key |
| **连续打卡** | 从完成记录整体回算，不需要手动维护。当天还没完成时不清零，从昨天接着数 |
| **成长等级** | 每完成 5 个任务升 1 级，同样由完成记录算出 |
| **成就徽章** | 任务完成 1/3/5/10/20/50、胶囊开启 1/2/3/5/10、连续打卡 2/3/7/14/30/100 天，里程碑自动解锁 |
| **导入导出** | 全部数据导出成一个 JSON 文件；换设备或重装浏览器后导入即可恢复。支持合并与覆盖两种导入方式，导入前自动存快照可回滚 |
| **中英双语** | 界面支持中文与英文，设置页随时切换；新增一门语言只需加一个 JSON 文件 |
| **本地优先** | 没有账号、没有埋点、没有后端数据库。任务、胶囊、知识库、分身都存在你自己的浏览器里。**只有「对话」会联网**，见下 |

## 快速开始

需要 Node.js 18 或更高版本。

```bash
cd frontend
npm install
npm run dev
```

打开 <http://localhost:4113>。

构建静态产物：

```bash
npm run build     # 输出到 frontend/dist，纯静态，可直接托管
npm run preview   # 本地预览构建产物
```

跑测试：

```bash
npm test
```

## 数据存在哪里

**浏览器 IndexedDB**，数据库名 `timecapsule`。不经过网络，也不存在别的副本。

这带来一个必须记住的代价：**清除浏览器数据、使用无痕模式、或更换设备都会让数据消失。**
所以「设置 → 备份与恢复」里的导出不是可选项，而是唯一的保险。建议定期导出。

导入时会做完整的格式校验；任何一处不合法都会拒绝整份文件，不会留下半份数据。
导入与清空之前会自动保存一份快照，随时可以回滚一步。

## 对话与 AI

对话是**唯一会联网**的功能，用使用者自己的 API Key（在「设置 → AI 配置」里填）。

- **Key 只存在你自己的浏览器里**，每次请求随请求头带出去，服务端不保存、不记录；
  它也**不进备份文件**——备份是会被拷来拷去、发给别人的东西，把密钥写进去就是个陷阱
- 请求发往**同源的 `/api/ai`**（Cloudflare Pages Function，见 `frontend/functions/api/ai.js`），
  由它转发给模型厂商。同源，所以没有跨域问题
- 浏览器递过去的是**供应商代号**而不是地址，真正往哪发由 `src/domain/ai.js` 里的白名单决定。
  于是「把端点填成内网地址、让我们的函数替你请求一下」这类问题从设计上不存在
- 支持 DeepSeek / 火山方舟（豆包）/ 智谱 GLM / Kimi / OpenAI / OpenRouter，都是 OpenAI 兼容协议。
  设置页的「测试连接」会把这个 Key 实际可用的模型列表拉回来

本地开发时不需要装 wrangler：`vite.config.js` 里有一个 dev 中间件，它 **import 线上那同一个函数**
来执行，所以本地与线上跑的是同一份代码，**本地就能用真 Key 完整测一遍**。

> 部署提醒：项目里一旦有 `functions/`，Cloudflare Pages **默认每次请求都会调用函数**，
> 静态资源也会开始消耗「每天 10 万次」的函数额度。所以 `scripts/postbuild.mjs` 会生成
> 一个 `_routes.json`，只放行 `/api/*`——其余路径回到「静态请求不限量」那一档。

## 项目结构

```
frontend/          当前版本，唯一参与构建的目录
  src/
    domain/        纯业务逻辑（任务状态流转、胶囊开启规则、成就里程碑、
                   连续打卡与成长等级、备份校验、对话提示词与记忆召回），
                   无副作用，可在 Node 里单测
    storage/       存储适配器。IndexedDB / 内存两种实现，接口可替换——
                   二期接微信小程序时换成 wx.setStorage 即可，业务逻辑不动
    repository/    编排层。持有写入锁，一次业务操作里改动的多份数据
                   通过单事务一起落盘
    api/           页面唯一依赖的边界；也是全应用仅有的两处发网络请求的地方
                   （api/ai.js 与 api/chat.js）
    views/         页面      layouts/  布局      components/  组件
  functions/       Cloudflare Pages Function：同源转发到模型厂商（唯一出网的服务端代码）
  scripts/         构建后处理（生成静态托管的 SPA fallback 与 _routes.json）

legacy/            早期 Spring Boot + MySQL 版本的完整代码，**不参与构建**，
                   仅为对照与二期 AI 功能参考而保留。详见 legacy/README.md
```

## 技术栈

Vue 3 · Vite · Pinia · Vue Router · Element Plus · idb-keyval · Vitest ·
Cloudflare Pages Functions（仅用于转发对话请求）

没有后端服务、没有数据库、没有账号体系。唯一一段服务端代码是那个十几行的转发函数，
它不存任何东西。

## 一些实现上的取舍

- **时间统一用 `yyyy-MM-dd HH:mm:ss` 字符串**，不用时间戳。该格式定长且零填充，
  字典序恰好等于时间序，可以直接比较与排序，也不会踩时区的坑。
- **统计整体回算，不做增量累加。** 删掉一条已完成任务，连续打卡会跟着修正；
  累加器则会永久偏移。
- **写操作串行化。** 仓储层的操作都是「读集合 → 改内存 → 整体写回」，
  两个标签页同时操作会互相覆盖，因此用 Web Locks 做互斥。
- **多份数据一次落盘。** 本地没有数据库事务，`writeMany` 走的 IndexedDB
  单事务是唯一的等价手段，避免「任务改了但成就没发」这类半途状态。
- **Element Plus 组件按需、样式全量。** 主题文件里有约三十条与官方同优先级的
  组件精修规则，靠加载顺序生效；样式按需会把它们推进懒加载 chunk 而失效。
  详见 `frontend/vite.config.js` 的注释。
- **对话走同源转发，而不是浏览器直连。** 各家大模型的接口都不给浏览器发 CORS 头，
  直连必然被拦；走同源函数既没有跨域问题，也让「用户把端点填成内网地址」这类
  请求伪造无从下手——浏览器递过来的是供应商**代号**，地址由服务端白名单决定。
- **提示词与记忆召回是纯函数。** 它们原本散在 Spring 的 Service 里，只有起一整套
  后端才能验证；搬进 `domain/chat.js` 之后，每一条约束（150 字上限、
  「不要退化成通用助手」、挫败时先共情…）都能在 Node 里逐个断言。

## 路线图

- **第二版**：分身的一键蒸馏——把知识库里的材料读成画像与说话风格
  （现在这两项是手写的；对话所需的其余部分都已就位：Key 配置、材料召回、提示词）
- **与更多对象对话**：现在两种对话对象都基于**你自己的**材料。同一套机制其实不限于是谁——
  把某个人写过的东西导入知识库，就能蒸馏出那个人的画像。想做的方向是**历史人物**
  （示例数据里的庄子就是这么放进去的）与**导入朋友写的东西之后与朋友对话**
- **模型列表更全**：设置页的下拉靠供应商的 `/models` 接口，有的供应商只吐两三个
  （DeepSeek 就两个，还没法从列表里挑别的）。可以补一份常用模型的静态清单，
  或在接口给不出东西时给出推荐值
- **第二版**：微信小程序端（复用同一套存储适配器接口）
- **流式输出**：现在是非流式（等待时显示「那时的你正在回想…」）。
  改成 SSE 需要函数侧透传流，前端也要换掉当前的请求方式
- **备份校验提示的国际化**：界面文案与常见校验错误都已中英双语，剩下
  `domain/backup.js` 校验导入文件时产生的逐字段诊断信息（形如
  `data.tasks[0].title 应为字符串`）仍是中文。要改需要把错误收集从拼字符串
  换成结构化问题列表，见 [CONTRIBUTING.md](CONTRIBUTING.md)
- 外接存储适配器（自建服务器 / 对象存储同步）。接口契约已定，
  见 `frontend/src/storage/adapters/remote.js`
- 更多界面语言（欢迎翻译，加一个 JSON 文件即可）
